Strategy

Inference, infrastructure, kernels: three passes.

  1. 1

    Inference-level tuning

    Change how the model is served before touching anything else. Queue limits, batching behavior, serving flags and quantization are the cheapest wins, so they come first.

    max-num-seqs · continuous batching · vLLM serving flags · GPTQ INT8 and INT4

    300×+ lower p99 time to first token −37% cost per token vLLM flag benchmarks
  2. 2

    Infrastructure-level optimization

    Fix how requests, memory and replicas move through the serving infrastructure: request routing, KV-cache placement and offloading, multi-GPU parallelism, autoscaling and cloud provisioning.

    cache-aware routing · KV-cache offloading · tensor parallelism · autoscaling · Terraform · AWS

    vLLM routing PR #49204 KV offloading PR #48878 2.3× throughput on 2× T4 scale-from-zero PR #10133 All autoscaler fixes
  3. 3

    GPU kernel optimization

    When the profile shows the kernel is the limit, rewrite it. Memory access, tiling and register use are tuned against Nsight Compute and validated against a reference.

    Triton · CUDA · CuTe DSL · cuBLAS and cuBLASLt baselines · Nsight Compute

    7.1× B200 GEMM 1.81× faster attention on a T4

Selected work

Results I can put a number on.

  • B200 GEMM optimization

    Optimized Triton GEMM kernels against cuBLAS and cuBLASLt baselines on an NVIDIA B200 for the GPU MODE leaderboard, where the submission ranks 19 of 53.

    Triton · CUDA · cuBLAS · cuBLASLt · Nsight Compute
    7.1×752 → 106 µs

  • Multi-GPU LLM inference

    Tensor parallelism on 2× T4 with vLLM. Tuning max-num-seqs removed queueing and cut p99 time to first token from 37.1 s to 113 ms. Goodput under SLO rose about 93% for 4% higher cost per token, with 0 failures across 81 runs.

    vLLM · tensor parallelism · benchmarking
    2.3×478 → 1,091 tok/s

  • CUDA attention kernel optimization

    Shared-memory tiling on a Tesla T4. The QK kernel is 51% faster and the PV kernel 43% faster, with registers per thread down from 64 to 35. Validated against a CPU reference and profiled with Nsight Compute.

    CUDA · shared-memory tiling · Nsight Compute
    1.81×4.66 → 2.57 ms

  • Quantization benchmark

    FP16 against GPTQ INT8 and INT4 on a T4 with vLLM. INT4 gave 1.6× higher throughput, cut weight memory by 66% and raised KV-cache capacity by 53%, with zero failures across 1,500 requests.

    vLLM · GPTQ · INT8 · INT4
    −37%cost per token, INT4

  • vLLM serving flag benchmarks

    Controlled benchmarks of vLLM serving flags to measure how each one changes throughput, latency and GPU memory use.

    vLLM · Python · controlled experiments
    Flag sweepthroughput, latency, memory

Open source

Fixes contributed to the tools production runs on.

vLLM 2 pull requests

  • KV offloading failed for models with mixed KV-cache groups, such as DeepSeek-V4-Flash and Gemma-4.

    Added blocks_per_chunk for heterogeneous KV-cache groups, backward compatible with the existing block_size setting.

    MajorPR #48878

  • Distributed inference needed smarter request routing.

    Co-authored cache-aware routing using KV-cache signals, with Nick Hill. Merged July 27.

    MajorPR #49204

Kubernetes Autoscaler 6 pull requests

  • AWS scale-up from zero did not work with CSI volumes.

    Fixed it by populating the CSI node topology.

    MajorPR #10133

  • OCI template nodes did not use the registered ephemeral-storage.

    Used the node's registered ephemeral-storage for the template.

    MajorPR #9993

  • OCI node pool templates carried the wrong ephemeral-storage values.

    Fixed the ephemeral-storage values in the node pool templates.

    MajorPR #10513

  • An Exoscale instance pool configured with minSize 3 was silently read as 1, causing under-provisioning.

    Carried minSize and maxSize through. Backported to releases 1.32 and 1.33.

    PR #9506

  • A race in AWS placeholder instance deletion.

    Fixed the AWS placeholder deletion race.

    PR #10276

  • Auto Scaling calls ignored the AWS SDK endpoint environment variables.

    Honored those variables for the AWS Auto Scaling client.

    PR #9992

Kubernetes VPA 1 pull request

  • The admission controller failed on custom resources in Helm installs.

    Restored the missing */scale RBAC permissions.

    PR #9515

Also reviewed seven pull requests in kubernetes/autoscaler, across VPA, AWS template nodes and test tooling.
